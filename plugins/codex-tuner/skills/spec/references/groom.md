# Groom an issue

Read the issue, related decisions, relevant code and repository tracker rules. Resolve questions from those sources first. Ask about remaining choices together, with the consequence of each option. Capture decisions with reasons, acceptance checks, open questions and evidence.

An explicit request to groom the issue authorizes one grooming record there unless the task limits publication. Use the repository's tracker or its local Markdown issue. Update your existing record when possible. For read-only access or a request to prepare a draft, return the text locally. Keep this route on the issue: branch, spec and implementation belong to a subsequent task.

At spec time reuse the latest decisions approved by the user or a maintainer. Treat other comments as proposals. Reopen a decision only when new evidence changes it.
